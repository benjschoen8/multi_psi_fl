\section{Problem and Abstractions}
\label{sec:abstraction}

Clients in a model-heterogeneous federation hold private datasets whose
label spaces were defined independently. Client~$i$ owns a set of
\emph{eligible} classes $C_i$ (classes whose local sample count meets a
public minimum), and nothing guarantees that the local identifier of a
class carries any meaning outside client~$i$. Before any joint training
can attribute an update to a class, the federation needs a
\emph{relation table}: a partition of all local classes across all
clients into global classes, such that local classes describing the same
real-world concept share one global identifier.

We construct this table \emph{once}, offline, before federated training
begins, and keep it fixed for the whole run. The construction consumes
no cross-client ground-truth labels: it only uses information each
client is willing to publish about its own classes.

\subsection*{Objects}
Four objects recur in every variant of the protocol.

\begin{itemize}
\item \textbf{Masking.} $\pi_i$ is client~$i$'s private permutation from
local ids to masked ids. Every index that leaves client~$i$ is a masked
id $\hat a=\pi_i(a)$; real ids never appear on the wire, and client~$i$
resolves $a=\pi_i^{-1}(\hat a)$ locally.
\item \textbf{Per-class query.} Client~$i$ summarizes class~$a$ as a
vector $s_i[a]\in\Real^{d}$, unit-normalized. The variants differ
\emph{only} in how $s_i[a]$ is produced: from a description
(\S\ref{sec:exact}, \S\ref{sec:attn}), from image affinity to public
probes (\S\ref{sec:fuzzy}), or from both (\S\ref{sec:filter}).
\item \textbf{Ladder.} $\Delta=\{\delta_1>\dots>\delta_m\}$ is a public,
decreasing list of similarity thresholds. A pair is scored by how many
rungs it clears,
\begin{equation}
R[a,b]=\sum_{\delta\in\Delta}\Ind\!\left\{s_i[a]^{\!\top} s_j[b]>\delta\right\},
\label{eq:rank}
\end{equation}
so $\delta$ is a similarity threshold, not a distance tolerance, and $R$
is a coarse ordinal rank rather than a real-valued score. Revealing $R$
instead of the inner product is what keeps the comparison cheap under
encryption and coarse in what it leaks.
\item \textbf{Selection.} $\OneSided(R)$ keeps $(a,b)$ when $b$ is the
unique argmax of row~$a$ with positive rank; $\Mutual(R)=\{(a,b)\in
\OneSided(R):(b,a)\in\OneSided(R^{\!\top})\}$ keeps only pairs that
nominate each other. Zero rows and exact ties abstain, which is the
protocol's only built-in defence against an ambiguous class.
\end{itemize}

\subsection*{Pipeline}
All variants share the same three-stage shape:
\emph{(i)} each client builds a local table
$|\,\text{id}\,|\,\text{masked\_id}\,|\,\text{query}\,|$ without
communication; \emph{(ii)} each unordered client pair runs a matching
primitive on masked queries and emits weighted masked edges; and
\emph{(iii)} the aggregator merges the edges into global classes. Stage
\emph{(iii)} is common to everything that follows and is stated once, in
Algorithm~\ref{alg:global}: components grow by union--find in decreasing
edge weight, a merge that would place two classes of the \emph{same}
client in one component is rejected, and every surviving component,
singletons included, receives one global id.

\begin{algorithm}[t]
\caption{Global table from masked edges (shared stage)}
\label{alg:global}
\begin{algorithmic}[1]
\Require weighted masked edges $E$; every client's masked-id list
\Ensure $\GlobalTable=|\,\text{global\_id}\,|\,\text{client\_id}\,|\,\text{masked\_id}\,|$
  \State every $(i,\hat a)$ starts as its own component
  \For{$(i,\hat a,j,\hat b,w)\in E$ in decreasing $w$}
    \State $A,B\gets$ components of $(i,\hat a)$ and $(j,\hat b)$
    \If{$A=B$} \State \textbf{continue} \EndIf
    \If{$A\cup B$ would contain two classes of one client}
      \State reject the merge \Comment{same-client constraint}
    \Else\ \State merge $A$ and $B$
    \EndIf
  \EndFor
  \State assign one global id per component, singletons included
  \State \Return $\GlobalTable$
\end{algorithmic}
\end{algorithm}

During training the aggregator addresses a global class~$g$ by querying
each participating client with the masked id assigned to $g$; the client
maps it back locally and answers with the authorized update. The table
is therefore the only cross-client semantic object the federation ever
needs.

\section{Exact PSI Baseline}
\label{sec:exact}

The cleanest way to state the problem is to assume it away: suppose a
public vocabulary $W$ exists, and every client describes a class by
drawing keywords from $W$. Two clients holding the same concept then
write \emph{literally the same string}, and alignment reduces to a set
intersection, which private set intersection (PSI) already solves.
Algorithm~\ref{alg:psi} is the primitive in the only form we need: two
parties learn which elements they share and nothing about the elements
they do not.

\begin{algorithm}[t]
\caption{$\ExactPSI$ (primitive, abstract)}
\label{alg:psi}
\begin{algorithmic}[1]
\Require party $i$'s labeled set $\{(\hat a,\mathrm{desc}_i[a])\}$, party $j$'s $\{(\hat b,\mathrm{desc}_j[b])\}$
\Ensure the matched label pairs, and nothing else
  \State both parties encode their elements under a shared PSI encoding
  \State run the PSI functionality on the encoded sets
  \State \Return $\{(\hat a,\hat b): \mathrm{desc}_i[a]=\mathrm{desc}_j[b]\}$
  \Statex \Comment{non-matching descriptions stay hidden from both sides}
\end{algorithmic}
\end{algorithm}

Algorithm~\ref{alg:rt-exact} builds the relation table on top of it.
Clients only ever exchange masked ids, so the output of the pairwise
stage is already in the form Algorithm~\ref{alg:global} consumes, and
every edge carries unit weight because exact equality admits no degrees
of confidence.

\begin{algorithm}[t]
\caption{Relation table via exact PSI}
\label{alg:rt-exact}
\begin{algorithmic}[1]
\Require eligible classes $C_i$, shared vocabulary $W$
\Ensure masked edges $E$ for Algorithm~\ref{alg:global}
  \Statex \textbf{Phase 1 --- local, no communication}
  \For{each client $i$, each class $a\in C_i$}
    \State $\hat a\gets\pi_i(a)$;\ \ choose $\mathrm{desc}_i[a]\subseteq W$
    \State store $(a,\hat a,\mathrm{desc}_i[a])$ locally
  \EndFor
  \Statex \textbf{Phase 2 --- pairwise, no aggregator}
  \State $E\gets\emptyset$
  \For{each client pair $i<j$}
    \State $E_{ij}\gets\ExactPSI$ on the two description sets
    \State add $(i,\hat a,j,\hat b,1)$ to $E$ for $(\hat a,\hat b)\in E_{ij}$
  \EndFor
  \State \Return $E$
\end{algorithmic}
\end{algorithm}

The baseline is instructive precisely because its assumption fails in
our setting. Clients are independent institutions, possibly in different
countries; they write descriptions in their own language, at their own
granularity, without knowing what the other clients hold. There is no
$W$ to agree on, and string equality between ``the handwritten digit
five'', ``\emph{cinco}'' and its Chinese counterpart is
empty. Everything that follows replaces equality with \emph{graded
similarity}, while keeping the masking and the pairwise structure of
Algorithm~\ref{alg:rt-exact} intact.

\section{Fuzzy PSI and Affinity Queries}
\label{sec:fuzzy}

\subsection{The fuzzy primitive}
Relaxing equality to similarity changes what the primitive must compute:
instead of testing $x=y$, the parties test a \emph{similarity}
$\aff(x,y)$ against a ladder and reveal only the resulting rank
\eqref{eq:rank}. Algorithm~\ref{alg:fpsi} states this as
$\FuzzyPSI$. The receiver holds the decryption key and obtains the rank
matrix; the sender learns nothing, because each rung's comparison value
is multiplied by an independent fresh random positive scalar before it
travels back, so only its sign survives. An optional mask $M$ restricts
which pairs are evaluated at all.

\begin{algorithm}[t]
\caption{$\FuzzyPSI(s_i,s_j,\Delta,M)$ (primitive, abstract)}
\label{alg:fpsi}
\begin{algorithmic}[1]
\Require unit rows $s_i[a],s_j[b]$ in a compatible space; ladder $\Delta$; allowed mask $M$
\Ensure rank matrix $R$ with $R[a,b]$ as in \eqref{eq:rank}, masked by $M$
  \State receiver $j$ generates a homomorphic context, keeps the secret key
  \State $j$ sends its encrypted, packed coordinates to sender $i$
  \For{each allowed pair $(a,b)$ and each $\delta\in\Delta$}
    \State $i$ evaluates the encrypted inner product $c_{ab}$
    \State $i$ returns $(c_{ab}-\delta)\cdot r$ with fresh random $r>0$
    \State $j$ decrypts, keeps only the sign, and increments $R[a,b]$
  \EndFor
  \State \Return $R$ to $i$
  \Statex \Comment{a plaintext evaluation of \eqref{eq:rank} is the reference mode}
\end{algorithmic}
\end{algorithm}

\subsection{Affinity as the query}
The remaining question is what vector to compare when the parties share
no vocabulary. The answer is to describe a class \emph{indirectly},
through its relation to objects both parties already possess. Let $F$ be
a public frozen image encoder and $P=\{p_1,\dots,p_m\}$ an ordered
public set of unlabeled probes --- drawn from datasets no client trains
on, so that a probe carries no client's label information. With
$h_p=F(p)-\mu$ the mean-centered probe features and $r_i(a)$ the
mean-centered feature of class~$a$'s samples, the affinity coordinate is
\begin{equation}
\aff_i(a,p)=\cos\!\big(r_i(a),h_p\big),
\end{equation}
and the class query $s_i[a]$ is the row
$\big(\aff_i(a,p_1),\dots,\aff_i(a,p_m)\big)$, centered across probes
and re-normalized. Because the probe list is ordered and public, two
clients' rows live in the \emph{same} coordinate system by
construction --- the one thing the parties must agree on in advance is
this anchor set, nothing else. Raw images never leave a client; probe
labels are never used.

Algorithm~\ref{alg:rt-aff} is the resulting protocol: affinity profiles
go straight into the fuzzy primitive, and the surviving mutual matches
become edges weighted by their rank, so that a confident pair is merged
before a marginal one in Algorithm~\ref{alg:global}.

\begin{algorithm}[t]
\caption{Relation table via affinity profiles and fuzzy PSI}
\label{alg:rt-aff}
\begin{algorithmic}[1]
\Require eligible classes $C_i$; public encoder $F$; ordered probes $P$; ladder $\Delta_A$
\Ensure weighted masked edges $E$
  \Statex \textbf{Phase 1 --- local}
  \For{each client $i$, each class $a\in C_i$}
    \State $s_i[a]\gets$ normalized affinity profile of $a$ over $P$
    \State store $(a,\pi_i(a),s_i[a])$ locally
  \EndFor
  \Statex \textbf{Phase 2 --- pairwise}
  \State $E\gets\emptyset$
  \For{each client pair $i<j$}
    \State $R_A\gets\FuzzyPSI(s_i,s_j,\Delta_A,\Ind)$
    \State add $(i,\pi_i(a),j,\pi_j(b),R_A[a,b])$ to $E$ for $(a,b)\in\Mutual(R_A)$
  \EndFor
  \State \Return $E$
\end{algorithmic}
\end{algorithm}

This variant needs no text at all, which is also its weakness: two
visually similar but semantically distinct classes (a handwritten
\texttt{1} and a handwritten \texttt{7}) are near-neighbours in probe
space, and nothing in the protocol can separate them.

\section{Cascading a Text Stage with an Image Filter}
\label{sec:filter}

Text and image evidence fail in different places. A description
distinguishes \texttt{1} from \texttt{7} but can be misleading across
languages and granularities; an affinity profile is language-free but
blind to semantics. Cascading them keeps a pair only when both agree.

Algorithm~\ref{alg:rt-filter} runs the text stage first, on embedded
descriptions, and uses its surviving pairs to define an allowed mask for
the image stage. The mask spans the Cartesian product of the endpoints
that survived the text stage, so the image stage re-ranks a candidate
against its plausible competitors instead of against a single nominee;
mutual matching is then applied inside that masked matrix and the two
ranks are added into the edge weight.

\begin{algorithm}[t]
\caption{Text candidates filtered by image affinity}
\label{alg:rt-filter}
\begin{algorithmic}[1]
\Require descriptions $d_i[a]$ with aligned text encoders; affinity profiles $s_i$; ladders $\Delta_T,\Delta_A$
\Ensure weighted masked edges $E$
  \Statex \textbf{Phase 1 --- local}
  \For{each client $i$, each class $a\in C_i$}
    \State $t_i[a]\gets$ unit embedding of the description $d_i[a]$
    \State $s_i[a]\gets$ normalized affinity profile of $a$ \Comment{\S\ref{sec:fuzzy}}
  \EndFor
  \Statex \textbf{Phase 2 --- pairwise cascade}
  \State $E\gets\emptyset$
  \For{each client pair $i<j$}
    \State $R_T\gets\FuzzyPSI(t_i,t_j,\Delta_T,\Ind)$ \Comment{text stage}
    \State $E'_{ij}\gets\Mutual(R_T)$
    \State $M\gets$ indicator of the endpoint sets of $E'_{ij}$
    \State $R_A\gets\FuzzyPSI(s_i,s_j,\Delta_A,M)$ \Comment{image stage}
    \State $E_{ij}\gets E'_{ij}\cap\Mutual(R_A)$
    \State add $(i,\pi_i(a),j,\pi_j(b),R_T[a,b]+R_A[a,b])$ for $(a,b)\in E_{ij}$
  \EndFor
  \State \Return $E$
\end{algorithmic}
\end{algorithm}

The cascade is asymmetric on purpose: the image stage can only
\emph{remove} text candidates, never restore a pair the text stage
rejected. That bias towards precision is appropriate here, since a wrong
merge corrupts every subsequent training round, whereas a missed merge
only leaves a class as its own singleton global id.

Two assumptions in Algorithm~\ref{alg:rt-filter} are still too strong.
First, comparing $t_i[a]$ with $t_j[b]$ by inner product presumes the
clients' text encoders share a coordinate system; independently chosen
multilingual encoders do not. Second, a description is compressed into
one vector, so a long phrase dilutes the one word that identifies the
class. Section~\ref{sec:attn} removes both.

\section{Keyword Attention over Public Anchors}
\label{sec:attn}

\subsection{From descriptions to anchor coordinates}
Each client writes, for each of its classes, a short list of
\emph{keywords} in its own language, e.g.\
$\{\text{``digit''},\text{``five''}\}$ or
their Chinese or Japanese equivalents. Keywords are encoded
\emph{individually}, never concatenated into a sentence, so the
identifying token keeps its own vector.

The coordinate system is supplied by a public, ordered list of text
anchors $A$, agreed in advance exactly like the image probes. Client~$i$
embeds the anchors with \emph{its own} encoder $E_i$ to obtain anchor
keys $K_i$. A class is then expressed not by where its keywords sit in
$E_i$'s space, but by \emph{how its keywords attend to the shared anchor
list} --- an attention distribution indexed by anchor position. Since
the index is the public anchor order, two clients using different
encoders produce comparable rows without any encoder alignment,
projection head or trained parameter.

Two corrections make the distribution usable as a fuzzy-PSI query.
Keywords are weighted by a local inverse document frequency, so a term
every class repeats (``digit'') counts for less than one that separates
classes (``five''); and the attention vector is passed through a
logarithm and whitened against the anchor-key spectrum, which prevents a
few dominant anchors from deciding every comparison.
Algorithm~\ref{alg:attn} states the flow.

\begin{algorithm}[t]
\caption{Keyword-attention coordinates (per client)}
\label{alg:attn}
\begin{algorithmic}[1]
\Require public ordered anchors $A$; local encoder $E_i$; keyword lists $D_i[a]$; temperature $\tau$
\Ensure text query $z_i[a]$, indexed by the public anchor list
  \State $K_i\gets\Unit([E_i(w)]_{w\in A})$, centered across anchors
  \State $W_i\gets$ whitening built from the spectrum of $K_i$
  \State $\mathrm{df}_i(w)\gets$ number of own classes whose keywords contain $w$
  \For{each class $a\in C_i$}
    \For{each keyword $k\in D_i[a]$}
      \State $q_k\gets\Unit(E_i(k))$ \Comment{encoded separately}
      \State $\alpha_k\gets\mathrm{softmax}(q_k K_i^{\!\top}/\tau)$ \Comment{attention over anchors}
      \State $w_k\gets$ normalized inverse-document-frequency weight
    \EndFor
    \State $\bar\alpha_i[a]\gets\sum_k w_k\,\alpha_k$
    \State $z_i[a]\gets\Unit\big((\log\bar\alpha_i[a]-\text{mean})\,W_i\big)$
  \EndFor
  \State \Return $z_i$
\end{algorithmic}
\end{algorithm}

Used on its own, $z_i$ simply replaces $t_i$ in the text stage: run
$\FuzzyPSI(z_i,z_j,\Delta_T,\Ind)$ and keep the mutual matches. This is
the text-only variant.

\subsection{Precision-first matching}
\label{sec:precision}
The variant actually deployed combines $z_i$ with the two image signals
of \S\ref{sec:fuzzy} --- the probe-affinity profile $s_i$, and the
\emph{full} feature vector $v_i[a]$ of the class, which is used solely
to verify a nomination. The decision rule, Algorithm~\ref{alg:precision},
is built so that an edge is emitted only when the evidence is both
\emph{top-rung} and \emph{unrivalled}.

\begin{algorithm}[t]
\caption{Precision-first attention--affinity matching (deployed)}
\label{alg:precision}
\begin{algorithmic}[1]
\Require $z_i$ (Alg.~\ref{alg:attn}); profiles $s_i$; full features $v_i$; ladders $\Delta_T,\Delta_A,\Delta_V$; floor $\eta$; margin $\gamma$
\Ensure weighted edges $E$ and supported-pair set $H$
  \State $E,H\gets\emptyset$
  \For{each client pair $i<j$}
    \State $R_T\gets\FuzzyPSI(z_i,z_j,\Delta_T,\Ind)$ \Comment{text}
    \State $M\gets\Ind\{R_T>0\}$
    \State $R_A\gets\FuzzyPSI(s_i,s_j,\Delta_A,M)$ \Comment{affinity, text-masked}
    \State $R_V\gets\FuzzyPSI(v_i,v_j,\Delta_V,\Ind)$ \Comment{verification, \emph{unmasked}}
    \For{each candidate pair $(a,b)$}
      \State $T\gets$ [text rank is top-rung]; $I\gets$ [affinity rank is top-rung]
      \State \textbf{skip} unless $T\vee I$ and the verification rank clears the floor $\eta$
      \State $q\gets$ best verification rank of any rival of $a$ or of $b$
      \If{$(T\wedge I$ and $R_V[a,b]\ge q-\gamma)$ \textbf{or} $R_V[a,b]\ge q+\gamma$}
        \State accept: weight $(a,b)$ by the three ranks; add the pair to $H$
      \Else\ \State record $(a,b)$ as \emph{uncertain} for local review
      \EndIf
    \EndFor
    \State add the accepted pairs of $\Mutual$ to $E$
  \EndFor
  \State \Return $(E,H)$
\end{algorithmic}
\end{algorithm}

$H$ optionally strengthens Algorithm~\ref{alg:global}: a merge is
rejected unless every cross-component pair it would create is itself
supported, so a global class cannot be assembled from a chain of
pairwise matches that were never individually verified. The price is
that the aggregator sees $H$ in addition to the selected edges, and that
recall drops when observations are sparse.

\subsection{What ``precision-first'' changes}
\label{sec:diff}
The earlier attention variant fused the two ranks additively: a pair
scored $R_T|\Delta_A|+R_A|\Delta_T|$, was required to be top-rung on at
least one ladder, and then went through mutual matching. It has no
verification stage and no consistency constraint.
Table~\ref{tab:precision} contrasts the two.

\begin{table}[t]
\caption{Fusion attention vs.\ precision-first attention}
\label{tab:precision}
\centering
\small
\begin{tabular}{@{}p{0.26\columnwidth}p{0.3\columnwidth}p{0.3\columnwidth}@{}}
\toprule
 & \textbf{Fusion} & \textbf{Precision-first} \\
\midrule
Signals & text rank, affinity rank & text rank, affinity rank, full-feature verification \\
Combination & weighted sum of ranks & conjunctive test with a rival margin $\gamma$ \\
Rival check & implicit, via mutual matching & explicit: the nominee must beat \emph{every} rival by $\gamma$ \\
Masking & affinity computed on all pairs & affinity masked by text; verification deliberately unmasked \\
Abstention & ties and zero rows only & also below the floor $\eta$, or inside the margin: logged as uncertain \\
Global stage & weight-ordered merge & merge additionally constrained by $H$ \\
Failure mode & a strong text rank can carry a weak affinity rank & a correct pair can be dropped for lack of support \\
Cost & two rank matrices & three rank matrices, plus $H$ disclosed to the aggregator \\
\bottomrule
\end{tabular}
\end{table}

Two design points deserve emphasis. First, the verification stage is run
\emph{unmasked}: if rivals were hidden by the text mask before the margin
test, the margin would be computed against a truncated field and would
manufacture confidence rather than measure it. Second, the rule is
asymmetric in a way that matches the cost structure of the downstream
task --- when text and affinity agree at the top rung, a near-tie in
verification is tolerated ($q-\gamma$); when only one of them fires, the
pair must win verification outright ($q+\gamma$).

\section{Summary of Variants}
\label{sec:summary}

\begin{table}[t]
\caption{Relation-table variants}
\label{tab:variants}
\centering
\small
\begin{tabular}{@{}llp{0.34\columnwidth}@{}}
\toprule
\textbf{Variant} & \textbf{Alg.} & \textbf{Query and decision} \\
\midrule

Every variant outputs the same object --- weighted masked edges for
Algorithm~\ref{alg:global} --- and therefore plugs into federated
training unchanged. The table is built once, before the first round, and
training itself only performs generator aggregation and global-model
updates under the fixed mapping.
